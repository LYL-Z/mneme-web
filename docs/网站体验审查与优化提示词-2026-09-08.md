# Mneme 网站体验审查与优化提示词

日期：2026-09-08。范围：现有 React 前端、Hono API、样式与导入逻辑；本地现有构建的桌面页面、搜索和 390×844 阅读页。本文是分析和实施规格，未修改网站业务代码、数据库或知识库原文，未部署。

方法：双代理独立评审（A：design_review；B：technical_review），主代理补充浏览器观察与 Apple/Anthropic 官方资料核对。A 的 Nielsen 评分为源码启发式判断，不是用户实验或性能测试分数。线上测试域名显示 CloudBase 中间提示，未继续进入，不能证明线上与本地构建一致。

## 结论

当前网站的长处是个人记忆的视觉主题已经成立；主要短板是展示结构先于作者工作结构。建议保留纸色、墨夜、青铜、星图与时间河，将主界面升级为“可连续工作的证据阅读工作区”，把展陈放进探索入口。Liquid Glass 应集中在导航、搜索和浮动操作层，正文使用稳定实底。Claude Code 的参考价值主要是上下文持续、面板组织、清晰状态和快捷操作。

这次只提出方案。第一轮应修复可靠性和阅读，再做材质与动效，最后补足章节材料闭环。编辑器、AI 写作和双向同步属于独立后续项目。

## 现状证据与优先级

| 维度 | 现有证据 | 改进方向 |
|---|---|---|
| UI | tokens.css 的全局 glass 使用 28px 模糊、阴影与大圆角；Archive 正文也应用 glass；桌面导航文字为 11px | 保留品牌色，限制玻璃覆盖面积，控制与正文分别设字阶；用可读性确定对比度 |
| UX | App 用 state 切九个同级空间，条件渲染卸载前一空间，无 URL/历史恢复 | 路由、返回、滚动位置、选择状态、最近阅读优先；探索与工作分组 |
| 功能区 | CommandK 的意象、卷章、问卷命中为 todo，点击仅关闭窗口并 console.log；时间线命中不携带事件位置 | 六类命中全部有精确目标；未实现项不可伪装成打开动作 |
| 内容区 | Stars 的规模展示含硬编码值，首页并列实时统计；Archive 渲染 Dataview 为代码块 | 统计带来源、时间与范围；动态查询转受控索引；保留原文查看入口 |
| 阅读 | Archive callout 重写首个段落 innerHTML；wiki 链接无 href；片段截取且不可定位 | 使用解析器而非字符串拼接；完整保留 callout 内容；真实链接和段落锚点 |
| 交互 | 检索与文档请求缺少过期响应保护；多处 catch 静默；错误与隔离混为一谈 | 取消请求/序列号保护、状态机、重试、焦点管理、中文输入法兼容 |
| 流畅性 | Gate 延时 2870ms；主空间切换 640ms；Graph 持续 rAF 重绘 | 跳过序章，操作即时反馈，短过渡；图谱按需绘制、后台暂停、减动效降级 |
| 响应式 | 390×844 实测正文向右裁切，九项导航只露部分且隐藏滚动条 | 文档单栏和宽内容局部滚动；主导航折叠/抽屉；真机核对 |

搜索实测：在时间线中检索“童年”，点击“卷·卷一·童年与底色”，搜索框关闭但仍留在时间线。该行为与 CommandK 的 todo 分支一致。

P0 内容可靠性：修复 callout 正文丢失机制；明确原始 HTML 策略并清洗输出。存在 HTML 注入风险路径不等于已发生攻击。

P1 工作连续性：精确检索跳转、URL/历史、阅读位置、请求竞态、错误恢复、移动正文溢出。

P2 设计质量：操作与阅读字阶、有限玻璃、短时动效、工作导航、按需侧栏、图谱功耗。

P3 新能力：章节来源清单、材料对照、待核工作队列。先维持只读，避免同时重建编辑器和同步系统。

## 建议的信息架构

主导航：工作台、资料、书稿、探索。全局搜索始终可见。

- 工作台：继续上次阅读/章节、最近材料、待核队列、数据同步时间。只展示真实存在的数据，未建设的能力不放假按钮。
- 资料：原文档案、人物、时间线、主题、他者之声。每项仍使用既有数据结构；文学化名称可作副标题。
- 书稿：序章与各卷、章节状态、关联材料、来源片段、待采项。五卷是当前工作框架，界面不应将它写死成永久结构。
- 探索：记忆恒星、人物星图、时间之河、意象博物馆。保留沉浸体验，但允许返回任务位置。
- 证据灯塔：既可独立进入，也应成为右侧来源检查器的全局入口。

桌面布局起点：左侧导航约 224–256px，中央可读正文，右侧来源检查器约 300–360px，右栏按需开启。正文目标约每行 32–40 个汉字，用户可调字体和宽度。以上是设计起点，需在真实长文与屏幕上校准。

中屏优先收起来源侧栏。手机采用单栏文档、目录抽屉、全局搜索和明确的返回入口。不要把桌面三栏等比例缩小。

## 九个空间逐项处理

| 空间 | 保留 | 下一步 |
|---|---|---|
| 记忆恒星 | 星体与个人记忆识别 | 变成可选探索首页；规模统计移次要位置，真实工作入口放首屏 |
| 时间之河 | 人生阶段与时间锚点 | 年份跳转、时间范围、人物/材料类型筛选、事件定位、纵向列表替代视图 |
| 人物星图 | Canvas 与关系分类 | 搜索/筛选、聚焦人物一跳邻域、位置恢复、键盘可操作人物列表；距离不表示亲密度 |
| 五卷书房 | 既有卷章组织 | 每章明确“有正文/只有提纲/待采”等真实状态；章节材料链；配置驱动卷结构 |
| 主题域 | 分类检索 | 查询、排序、分页或展开更多；保留筛选条件 |
| 意象博物馆 | 意象历次出现 | 展示来源、时间、所属章节、候选状态；重复出现不能直接证明文学意义 |
| 原文档案馆 | Markdown 与反链 | 完整渲染、目录锚点、搜索命中高亮、双文档对照、来源位置 |
| 他者之声 | 问答与同伴视角 | 显示说话人、记录日期、原件/二次总结属性；定位原段，不能变成人格结论 |
| 证据灯塔 | 已有待核/推断/回顾分类 | 从统计页扩展到具体项、出处、上下文和影响章节；条数不等于可信度 |

## 视觉与动效方案

1. 三类表面：稳定实底的阅读层、轻微层次的列表层、有限透明的操作浮层。玻璃用于顶栏、命令面板、浮动工具条和抽屉；长文、表格、证据片段不做折射。
2. 保留暖纸色与青铜作为品牌。降低重复希腊标签、纸纹、扫光和多层阴影的同时出现频率。控制文字使用系统无衬线，中文正文允许宋体/思源宋体回退。Windows 字体回退须实测。
3. 建议起始字阶：导航 13–14px、元信息 12–13px、正文 16–18px，行高约 1.8–1.95。不得把低对比度小字当作高级感。
4. 动效起始预算：按压反馈 80–120ms、菜单/工具提示 120–180ms、面板切换 180–260ms。它们是项目建议，非 Apple 官方硬性参数。耗时请求独立显示加载状态，不等待动画结束才响应。
5. 减动效、减少透明度、提高对比度分别设计；浏览器不支持相关系统偏好时提供站内手动开关。不支持 backdrop-filter 时退化到实底，保留可读性。
6. 图谱静止时停止重绘；在视图变化、模拟尚未稳定、数据变化时请求新帧。隐藏/不可见时暂停；必要时再评估 Worker，不能先把复杂度当作优化。
7. 保留 React/Vite/Hono/现有数据库，先用测量决定懒加载、缓存与拆包。不要因“苹果流畅”而换框架或叠加第二套动画库。

Apple Liquid Glass 的材料与流动性不能由一条 blur 声明等价实现。网页可以借鉴它对内容与控件的分层、轮廓反馈、可访问性适配；是否达到目标要看实际浏览器和设备，而不是 CSS 名称。

## 内容与数据合同

- Obsidian 为事实来源；网页展示导入快照并标注同步时间、数据范围和异常。不要把网页修改写回原文作为本轮默认能力。
- 来源至少含文档路径、稳定片段定位、记录日期、来源类型、核验状态。事实、解释、文学表达保持区分，评价归属到说话人。
- 核验状态不是整篇文章的单一可信分。一个段落也可能混有已确认时间、他人转述和作者回望，应允许分片段显示。
- 文档提及次数、共现次数、反链数均不可作为亲密度、重要性或真实性指标。
- 私密目录排除不是完整的隐私结论。API、搜索摘要、索引元数据、附件和导出都需要按同一范围检查；不在前端额外下载私密材料再隐藏。
- 公开范围与登录范围要区分。“公开层”不应让用户误以为可自由外发。未找到/无权限的外部口径可统一，网络故障不能伪装成内容缺失。
- 当前创作总纲仍写约 84 万字与时间顺序主线；用户本轮称百万字项目。把目标字数和卷结构做成读取规格的可配置字段，不擅自改写创作目标或重排知识库。
- 首页硬编码规模数据不能仅凭实现判断真假；应补来源和统计时点，不能自动把它们替换成推测数字。
- Dataview 不应在网页执行任意脚本。需要时转换为受控服务器查询；未支持语法提供明确的静态替代与原文入口。

## 验收方案

第一组：读者任务。检索六类材料分别抵达精确目标；从章节到人物到原文再返回，章节选择和滚动位置不丢；深链接刷新正确；快速输入无旧结果覆盖；中文输入法确认候选不误触打开。

第二组：内容可靠性。多行 callout、标题、引号、wiki 别名、标题锚点、嵌入、宽表格和代码块有代表性样例；清洗不吞正文；404、401、网络失败分别处理，且不泄露受限资源是否存在。

第三组：界面。390/768/1280/1440px 检查，长标题、空列表、错误状态和深浅主题一起检查。正文无横向裁切，宽表格可局部滚动。键盘可完成检索和阅读；弹层焦点受控且关闭后返回触发点；图谱有等价列表入口。

第四组：性能。记录设备、浏览器、构建模式、数据量、网络条件。LCP≤2.5s、INP≤200ms、CLS≤0.1 为 Web Vitals 的良好范围，现场数据按第75百分位判断；本地实验不能伪装成现场达标。图谱另录制拖动、缩放、空闲三种状态的帧时间与主线程占用。60Hz 单帧总预算约16.7ms，不代表JS可以占满。没有测量不要声称60fps或苹果级流畅。

## 可复制提示词一：可靠性与精确检索

```text
请基于 D:\The Memory\mneme-web 修复现有阅读与检索链。先读取适用 AGENTS.md、App.tsx、api.ts、Archive.tsx、CommandK.tsx 与 server/store 相关代码。保留现有框架、纸/夜主题和所有有效功能。

优先修复：多行 callout 正文被 innerHTML 替换截掉；原始 HTML 与 wiki 拼接的安全渲染；真实可键盘访问的内部链接及标题锚点；检索/阅读过期响应覆盖；网络错误被解释成未收录；意象/卷章/问卷命中点击无动作；时间线命中无法定位；中文输入法确认候选与Enter命令冲突；移动阅读正文裁切。
```


## 可复制提示词三：Liquid Glass 与克制的阅读表面

```text
请对 D:\The Memory\mneme-web 做有限范围的视觉升级。方向是现有暖纸、墨夜、青铜与记忆主题，结合Apple Liquid Glass的操作层分层及Claude Code工作区的紧凑、稳定、清晰。不要复制品牌标识或改变事实文案。

先检查tokens.css、liquid-glass.css、app.css和实际页面，输出表面/字阶/间距/圆角/阴影/动效token方案，再实施到顶栏、搜索、抽屉与阅读页。

正文、表格、证据片段采用稳定实底；玻璃限于操作浮层。减少全屏模糊、永久扫光、鼠标追光和重复阴影；导航使用清晰无衬线，正文保持中文长文阅读气质。避免大面积装饰让主要任务落到首屏以下。

同时提供深浅主题、减动效、减少透明度、增强对比度、不支持backdrop-filter的实底降级。检查Windows字体回退、键盘焦点、触控尺寸及390/768/1280/1440px布局。颜色与时长都以实际可读性和响应结果验收，禁止仅凭blur和spring命名声称苹果级效果。不得修改资料内容或部署。
```

## 可复制提示词四：可测量的系统流畅性

```text
请优化 D:\The Memory\mneme-web 的连续操作与渲染成本。先测量生产构建下的首页、搜索、长文、时间线拖动和图谱缩放，记录设备、浏览器、数据规模、帧时间、长任务与网络条件。

重点检查Gate约2.87秒阻塞序章、App的640ms整页动画、子组件stagger、Graph永久rAF、全局glass的blur/折射/跟随光、频繁卸载导致重复请求。不要假定所有效果都必须删除；用证据决定，保留品牌探索体验。

给出相同条件下优化前后数据。Web Vitals目标与现场/实验数据分开报告，不编造fps、改善百分比或苹果级达标结论。完成typecheck/build与必要回归，不自动部署。
```

## 可复制提示词五：书稿与证据闭环

```text
请在 D:\The Memory\mneme-web 现有五卷书房、档案馆与证据灯塔上建立只读章节材料工作流。先读取知识库的写作体系索引、实际存在的创作总纲及适用隐私规则；规则旧路径若缺失，应定位更名文件，不猜写内容。

以“章节→支撑材料→原文片段→待核项→回到章节”为闭环。每章展示实际存在的提纲/正文/材料状态；来源保留文档路径、片段锚点、时间、说话人、原始或二次材料属性与核验状态。把事实、作者回望、他人评价、推断与文学化重构区分呈现。

提及次数不等于重要性，共现不等于亲密关系，待核数量不等于不可信程度。人物同名不能自动合并。私密材料不得进入前端缓存、全文索引、搜索摘要或导出。尚无来源的字段显示未建立，不生成假证据或自动心理画像。

先复用已有数据和入口；必要新增字段提供迁移与回滚方案，不改原始材料。该阶段不做编辑器、自动写作、自动归档或双向同步。用真实非私密章节核查闭环，列出数据库与前端各自的已完成项，再报告结果。
```
