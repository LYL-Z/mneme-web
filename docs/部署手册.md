## 1. 总体架构

```
浏览器（口令登录 → mneme_k cookie 门禁，同源）
        │ HTTPS
        ▼
CloudBase 云托管「mneme」容器（0.25C / 0.5G，MinNum=1）
  ├─ Hono API（server/server.mjs）           ← 唯一对外进程
  ├─ 静态前端（site/ 或 web/dist，与 API 同源打包）← 零跨域、零 CDN 依赖
  ├─ 只读 SQLite（/app/ingest/mneme.db，35MB，打进镜像）← 运行时唯一读路径
  └─ （可选）MNEME_PG 存在时切换 store-pg.mjs 适配器
        ▼
CloudBase PostgreSQL（pgdb-apm9afgf，共享集群）
  └─ 全量数据副本：13 表 13,558 行（可审计、可迁移、可恢复）
```

**设计要点：**

- **运行时零凭证**：容器内只读 SQLite 是唯一读路径，镜像自带数据，不需要任何数据库连接串、不暴露任何密钥；公网仅暴露一个 HTTPS 端点，入口由 mneme_k cookie 门禁。
- **PG 是云端档案库，不是运行时依赖**：全量数据（截至 2026-09-11：documents 692〔公开 646 / 私密 46〕、entities 281、entity_mentions 1,899、wikilinks 10,248、timeline_events 46、volumes 6、chapters 35、imagery 53、imagery_occurrences 67、questionnaires 26、evidence_spans 484、year_density 27、audit_runs 1，合计 13,865 行）已通过 HTTP 网关一次性灌入。它的价值是**可审计、可随时导出迁移**；0.25C 小规格容器下，容器内 SQLite 的查询延迟显著优于跨网关访问 PG。
  > 行数会随 vault 增删变化；以 `ingest/mneme.db` 为准重新统计即可，不必手改本表。
- **共享集群限制的绕行方案**：本环境 PG 为 SHARED 共享集群——无内网地址、外网 IPv4 不可开通、密码不可重置，**TCP 直连彻底不可行**。灌数据走的是 HTTP 网关 REST 通道（`https://{envId}.api.tcloudbasegateway.com/v1/rdb/rest/{table}`，PostgREST 风格），见 §4。若未来升级独享集群，`server/pg-load.mjs`（TCP 版幂等灌库）与 `server/store-pg.mjs`（运行时 PG 适配器）已就位，把 `MNEME_PG` 环境变量指向连接串即可切换。

**API 调用示例（携带口令）：**

```bash
curl -H "Authorization: Bearer $MNEME_TOKEN" \
  https://mneme-biography.app.workbuddy.link/api/overview
```

> `Authorization: Bearer <TOKEN>` 自 v8 起在**门禁层**生效（此前只在文档里写了、
> 服务端实际只认 cookie，实测 401）。现 cookie 与 Bearer 二选一即可。

主要端点：`/api/health`（免鉴权健康检查）、`/api/overview`、`/api/domains`、`/api/timeline`、`/api/entities`、`/api/entities/:id`、`/api/doc/:path`、`/api/search?q=`、`/api/imagery`、`/api/volumes/:code`、`/api/chapter/:code/:seq`、`/api/questionnaires`。

**三级可见性**（v8 起由 `server/privacy.mjs` 单点定义，三处调用方共用）：

| 层级 | 判定 | 未登录/未解锁时的表现 |
| --- | --- | --- |
| 公开 | 默认 | 200 正常返回 |
| 私密（`私人资料/`、`隐私/`） | `isPrivatePath` | **404**——与「不存在」不可区分，不可枚举 |
| 绝密（绝密人物全宗、卷二/卷三、非父母卷问卷） | `isSecretPath` / `isSecretText` / `SECRET_VOLUMES` | **403**——明确提示需解锁 |

**改口令**：云托管控制台 → 服务 mneme → 服务设置 → 环境变量，改 `MNEME_TOKEN` 后保存（触发滚动重启），随后在部署目录同步修改并重新部署（见 §3）。

| `MNEME_SECRET` | 源码内置开发默认值 | 绝密层解锁口令（**生产必须覆盖**；也可写在 gitignore 的 `privacy.local.json`） |
| `MNEME_SECRET_NAME` | — | 绝密人物姓名过滤（生产必须设置；不要写入仓库） |

| `MNEME_DB` | `ingest/mneme.db` | SQLite 只读库路径 |
| `MNEME_STRICT` | 云模式默认开启 | 口令缺失、仍为内置开发值、或未设绝密姓名过滤则**拒绝启动**。回滚设 `0` |

## 4. 数据管道（重扫描 / 日常增量）

**方向是单向的**：Obsidian 知识库 → 本机 ingest → 网站。网站（本机与云端）都不写回 vault：`PUT /api/source` 一律 501，写作台已撤。划线、足迹、丝带、现场 p75 只是这台浏览器自己的记录。

**本机已有自动跟上**：`server/sync-watch.mjs` 监听公开层 `.md`（跳过 `私人资料/` / `隐私/`）。改完约 2 秒排队重建 `ingest/mneme.db`，本机 `http://127.0.0.1:8421` 下次读库即是新内容。云模式（`MNEME_MODE=cloud`）故意不开监听、不开写回。

**线上要变，仍须发布一次**：本机 `npm run release`（已含库同步）→ 再部署 `deploy/`。没有「知识库一改，公网站立刻变」的通道——那会把私密库打到公网。

**全流程**：vault 变更 → 本地重建 SQLite → （可选）重灌 PG → 重部署容器。

```bash
cd "D:\The Memory\mneme-web"

# ① 重建本地 SQLite（先停掉本地 dev 服务）
node --experimental-sqlite ingest/ingest.mjs     # 产出 ingest/mneme.db（vault 只读扫描）

# ② 同步进 deploy 并重部署（见 §3）

# ③ （可选）重灌云端 PG 档案库——共享集群走 HTTP 网关 REST 通道：
#    前置：管理端临时开启匿名登录 + 对 anon 临时 GRANT INSERT（完成立即回收，见下）
#    需先清空既有数据（脚本按主键直插，非幂等）：
#    TRUNCATE public.documents, public.entities, public.entity_mentions, public.wikilinks,
#             public.timeline_events, public.volumes, public.chapters, public.imagery,
#             public.imagery_occurrences, public.questionnaires, public.evidence_spans,
#             public.year_density, public.audit_runs;
cd ingest
MNEME_PUBKEY=<Publishable Key> MNEME_DEVICE_ID=mneme-pgloader-6f1c2b8a \
  node --experimental-sqlite pg-load-rest.mjs
#    灌完必须恢复安全原状：
#    REVOKE INSERT ON <13 表> FROM anon; REVOKE USAGE ON SCHEMA public FROM anon;
#    并在身份认证设置关闭「匿名登录」
```

**匿名登录要点**（openapi 契约）：`POST /auth/v1/signin/anonymously` 必须携带 `x-device-id` 请求头（客户端随机生成并缓存，长度 <72，同一 device id 复用同一匿名用户），缺失时报「请在请求头添加设备id」。

**升级独享集群后的简化解法**：开通外网 IPv4 / 内网地址后，直接用 `server/pg-load.mjs`（TCP 直连版，幂等、事务化），无需再走 REST 通道。

## 5. 回滚

**代码回滚**（部署记录保留历史版本）：

1. CloudBase 控制台 → 云托管 → 服务 mneme → 部署历史，找到上一个稳定版本的 RunId；
2. 版本详情 →「回滚到此版本」（或 MCP：`queryCloudRun(action="getDeployRecords")` 查历史 → `manageCloudRun(action="traffic", trafficOp="rollback")` 回滚到上一稳定版本）；
3. 若灰度发布场景：`trafficOp="set"` 调整稳定/灰度流量比例（两者之和=100）。

**数据回滚**：

- 运行时数据在镜像内（mneme.db），回滚到旧版本镜像即回滚数据；
- 云端 PG 档案库可随时以 `TRUNCATE` + 重新灌库恢复（§4），或从本地 `ingest/mneme.db`（Git 版本化于仓库外）重建。

## 6. 已知限制与注意事项

- **PG 共享集群无 TCP 通道**：运行时不要把 `MNEME_PG` 指向共享集群地址（连不上）；保持未设置即走容器内 SQLite。
- **mneme.db 打进镜像**：每次数据更新都需重部署（§3）；镜像约 34MB + 前端 ~3.7MB，构建约 2 分钟。
- **私密层治理口径（v4 起，不再是「零提取」）**：ingest 管线**会**把 `私人资料/`、`隐私/` 下的 md 扫进 `documents` 表并标 `is_private=1`，
  由「加密门禁」保护——未解锁时任何 API 出口都不会吐出私密路径或正文（文档请求返回 **404**，与不存在不可区分）。
  早期版本的手册与文案写的是「零提取」，与实现不符，已更正。
  核对方式：`node --experimental-sqlite ingest/test-privacy.mjs`（数据库级结构断言 P1–P6）。
- **本机代理**：本机 curl 测试需加 `--noproxy '*'`，否则代理拦截 127.0.0.1 与网关请求。
- **费用**：体验版环境（到期 2027-03-06）；MinNum=1 常驻 0.25C/0.5G 实例持续计费，若长期不访问可把 MinNum 改 0 接受冷启动。
