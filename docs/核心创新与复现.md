# 核心创新与复现方法

本文说明 ΜΝΗΜΗ **可以移植的装置技术**。它不是攻击手册，也不提供口令、绝密姓名或私密正文。

对标的是系统铬与编辑部网站的**组合方式**，不是声称发明了 WebGL 或 `backdrop-filter`。别人要的是：同一套约束下，如何做出「能读、能守、能在弱设备上活下来」的传记馆。

---

## 1. 单向知识库投影

### 问题

Obsidian 是写作现场。网站若可写回，隐私规则、来源状态和人物页会被「为了好看」污染。

### 做法

- ingest 对 vault **只读**。目录名属于私密层的文件**零读取**（连打开都不做）。
- 公开层敏感字段入库前掩码。
- 产物是 `ingest/mneme.db`（gitignore）与可选 `snapshot.json`。
- 网站 API 只读该库。划线、丝带、足迹停在浏览器。

关键文件：`ingest/ingest.mjs`（`PRIVACY_SEGS`、`INGEST_VERSION`）、`server/server.mjs`。

### 复现

1. 设 `MNEME_VAULT` 指向你自己的库根。
2. 把「绝对不能进站」的目录名放进与 `PRIVACY_SEGS` 等价的集合。
3. `node --experimental-sqlite ingest/ingest.mjs`（Node 22+）。
4. 改规则或版本号后设 `MNEME_INGEST_FULL=1`，不要幻想增量能重算全局 FTS / 实体。
5. 部署时**库文件必须与前端同批更新**。只更 JS、不更 db，检索会 500（v8.3 踩过）。

### 不要做

- 不要让网站表单写回 `.md`。
- 不要把 db、snapshot、vault 打进公开镜像。
- 不要在 ingest 里「顺便」读私密目录做统计——统计本身就是泄漏。

## 2. 三级可见性（公开 / 私密 / 绝密）

### 问题

历史上 `server.mjs`、`store.mjs`、`store-pg.mjs` 各写一套判定：锁了 `/api/doc`，漏了搜索、星图、时间线。旁路比漏洞更常见。

### 做法

**一个模块，所有出口调用。** `server/privacy.mjs` 是唯一事实来源。

| 层 | 未解锁时 | 目的 |
| --- | --- | --- |
| public | 正常返回 | 可读 |
| private | **404**，与「没有这页」相同 | 不可枚举 |
| secret | 目录/星图以锁定档出现；点开 **403**，走会话解锁 cookie | 知道有章，读不到正文 |

绝密姓名与口令：环境变量优先，其次本机 `privacy.local.json`（gitignore）。仓库里只有 `privacy.local.json.example` 空模板。

### 复现

1. 列出所有「能吐正文或实体名」的路由，做成清单。
2. 每一条都调用同一函数：`classify(path | entity) → public | private | secret`。
3. 私密：直接 `notFound`。不要 401/403（那会告诉扫描器「这里有东西」）。
4. 绝密：列表可出现标题与锁标记；`GET` 正文前检查解锁 cookie。
5. 写两个测试：`web` 脚本里的 `test:privacy` / `test:api`。**新增任何列表 API 必须先加进这两套。**
6. 章节级锁用配置的序号数组，不要把姓名写进前端包。

### 不要做

- 不要为了「友好错误」给私密层单独文案。
- 不要在 404 HTML 里回显请求路径里的私密片段。
- 不要把绝密姓名写进客户端常量「方便高亮」。

## 3. 设备壳先于首帧

### 问题

响应式若等 React 水合，鸿蒙 / iOS 会先画出桌面左栏，再跳成底栏。这是布局闪烁，不是「适配还没写完」。

### 做法

`web/index.html` 内联脚本在画任何组件前写入：

- `data-os`：harmony / ios / android / windows / mac / other
- `data-shell`：phone / tablet / desktop（短边、指针精度、宽度）
- `data-pointer`、`data-orient`、`data-display`（standalone）
- `--phone-bar`、`--vvh`

CSS 用属性选择器分壳，而不是只靠 `@media (max-width)`。

### 复现

1. 把探测脚本放在 `<head>`，**不要**放进 React。
2. 用 `visualViewport` 取宽高，避免移动浏览器工具栏把 `innerHeight` 拉来拉去。
3. `matchMedia('(hover: hover) and (pointer: fine)')` 区分真鼠标与触控假宽屏。
4. 底栏高度按 os 给不同 `--phone-bar`（鸿蒙手势条与 iOS 不同）。
5. 用真机或远程 UA 看第一帧，而不是只看水合后的截图。

### 不要做

- 不要用 UA 字符串当唯一安全边界（它只用于壳，不用于授权）。
- 不要在 CSS 里写死 375px 当手机。

## 4. 沉浸光感：玻璃只在铬上

### 问题

全站 `backdrop-filter` 会让长文发糊、耗电，并变成「又一个玻璃拟态模板」。华为 / 苹果把材质用在导航与层叠，不用在正文。

### 做法

`immersive.ts` 实现六特性，且只绑 `.chrome`：

1. 通透：`.chrome.glass` + `backdrop-filter`
2. 渐变模糊：滚动写入 `--nav-sc`（0 近透明 → 1 满糊）
3. 按压弹性：`:active` scale
4. 按压点光源：指针处 ripple
5. 材质流光：仅 exquisite，`::after` 慢扫
6. 智能反色：主题 + `--nav-sc` 改 `--chrome-ink`（不做全屏取样）

档位映射华为 MaterialLevel：

| 档 | 何时 |
| --- | --- |
| exquisite | 桌面、核多、内存足 |
| gentle | 中间档；鸿蒙手机最高通常到这里 |
| smooth | 减动效、省流、低核、FPS 哨兵降级 |
| adaptive | 按 `hardwareConcurrency` / `deviceMemory` / os / shell 自动选 |

液态玻璃四层在 `liquid-glass.css`：边缘高光、可选 SVG 置换、镜面扫光、指针光斑。**置换必须运行时探测**：`CSS.supports` 会对 `url()` 误报，Safari / Firefox 声明直接丢弃。

正文：`.surface` / `.ar-body`，实心底，宋体，段首缩进 2em，避头尾，不铺玻璃。

### 复现

1. 列出「铬」选择器：顶栏、侧栏、底栏、模态。只给它们 `.chrome.glass`。
2. 复制档位函数 `immLevel()` / `pickAdaptive()`，用 `data-imm` 驱动 CSS 变量，而不是每个组件 `if (phone)`。
3. 滚动监听写 `--nav-sc`，顶栏模糊与不透明度跟这一根轴走。
4. `prefers-reduced-motion` 与 `no-motion` 类强制 smooth，并关掉流光、粒子、置换。
5. 加 FPS 哨兵：连续掉帧则降档（`watchFps`）。降档是功能，不是失败。
6. 鸿蒙 / Android 在 `devices.css` 里减弱 blur 半径，不要和 macOS 桌面比糊。

### 不要做

- 不要给 `.ar-body`、卡片墙、统计数字加 `backdrop-filter`。
- 不要用固定 60 粒「通用粒子背景」冒充沉浸。
- 不要对外宣传「我们实现了苹果私有 Liquid Glass」。这是 Web 近似。

## 5. 霜面粒子消散

### 问题

弹窗 `display:none` 或透明度淡出，关掉致谢/偏好时像普通后台页。要对齐系统级「物料被拆掉」，需要**颜色来自原卡片像素**，不能换一套彩虹粒子。

### 做法（三层，对齐 ArkUI Particle 的分工）

1. **纹理采样**：把节点算好样式后塞进 SVG `foreignObject`，栅格化，按 3–7px 网格取样。粒子颜色 = 该格真实像素。
2. **GPU 驱动**：位置、速度、颜色、延迟、寿命一次上传；顶点着色器做欧拉积分（阻尼解析解 + 浮力 + 湍流）。每帧只更新 `u_time`。
3. **渲染**：`gl.POINTS` + 软边圆 + 加色混合。DOM 用噪声锋面 `clip-path` 与粒子同步，避免「粒子已经散了、卡片还完整待着」。

入口：`dismissGlass()` / `armSnapshot()`。打开弹窗就预采样，关闭零等待。`canAnnihilate()` 为假则立刻卸 DOM。

档位决定步长与粒数上限；手机再削一档，避免 60k 粒打 INP。

### 复现

1. 先做 **Canvas 2D 回退**（同一采样与物理），保证无 WebGL2 的机器也能关。
2. 采样：`getComputedStyle` 内联到克隆节点（跳过 `--*` 自定义属性），`XMLSerializer` → SVG → `Image` → `getImageData`。跨域字体失败时要能降级，不要抛穿整个关闭流程。
3. 关闭动画与 React 卸载解耦：先播，`done()` 回调里才 `setState` 卸树。
4. 用 `WeakMap` 缓存预采样。组件卸载必须取消未完成的 snapshot。
5. DPR 封顶 2。粒数按 `immLevel()` 与 `data-shell=phone` 量化。
6. 动画结束立刻 `loseContext` / 丢 canvas，防止隐页占 GPU。

参考实现：`web/src/annihilate.ts` 文件头注释即算法说明书。

### 不要做

- 不要用一张通用雪花 GIF。
- 不要在 `smooth` / `prefers-reduced-motion` 下仍跑 WebGL。
- 不要把致谢关掉。产品规定关闭致谢的同一手势才允许开背景曲。

## 6. 致谢门闩 + 单例背景曲

### 问题

浏览器自动播放策略、React StrictMode、热更新、多标签，会让音乐在输口令时就响，或两段重叠。若用「公告是否打开」当门闩，公告的初始状态是关的——登录页会被当成「已经看过致谢」。

### 做法

- 偏好默认 `on: true`，音量默认 0.3，写入 `localStorage mneme-bgm`。
- **能不能出声**另看 `sessionStorage mneme-anno === '1'`。只有关掉致谢时调用 `tryPlayBgm()`（同时标记已关、允许播放）。
- 登录成功必须清掉 `mneme-gate` / `mneme-anno` / `mneme-bgm-entered`，再刷新——否则同标签会跳过致谢。
- 全站一枚模块级 `Audio`。不要在 JSX 里挂 `<audio>`。
- `BroadcastChannel('mneme-bgm')`：后响起的标签通知先响的标签停。
- HMR dispose 时 `pause`。顺便清掉页面里残留的 `<audio src=...bgm.mp3>`。
- UI（`BGM.tsx`）只在 `gateDone && !annoOpen` 时出现；公告开着时 `stopBgm()`。

顺序：**口令 → 致谢 → 关闭致谢 → 音乐**。静音键仍可用；默认是开。

### 复现

1. 把「用户手势」和「偏好开关」拆成两个变量。手势没发生，偏好开也是静音。
2. 登录成功清会话标记。不要用「公告组件还没 mount」当「已经关过」。
3. `ensureAudio()` 单例；卸载 UI 不 `new Audio`。
4. 用真实的点击关闭致谢来测，不要用 `audio.play()` 在 `useEffect` 里碰运气。
5. 两个标签打开同一站点，只留一段。

### 不要做

- 不要在输入口令的 `keydown` 上「预热播放」。
- 不要为了调试把 `mneme-anno` 默认写成已关闭。

## 7. 每日星座（确定性生成艺术）

### 问题

程序化星空很容易假：随机点、假人名、每天刷新成噪音。传记馆要的是「今天的天空记住今天」，且星必须是库里的人。

### 做法（`DailySky.tsx`）

1. 取真实 `/api/graph`。失败不缓存（一次抖动不会让当天永远空白）。
2. 日期键 `YYYY-MM-DD` → FNV-1a → mulberry32。
3. 按提及量取前 90，洗牌，取 24 颗为当日星群。
4. 前 8 颗内圈（主星），其余外圈；半径与角度带种子抖动。
5. 星等 `2.4 + sqrt(mention) * 0.85`。颜色走人物分组，不另造。
6. 连线 = 这 24 颗之间**真实存在**的共现边，不补假边。
7. 画布固定高度，隐藏标签页停 rAF。状态分 `load | ok | empty | err`，失败可重试。

同一天刷新，同一片；换一天，换一片；永远不发明人物。

### 复现

1. 先有一张带 `mention` 与共现边的图。没有图就显示 empty，不要画装饰星。
2. 种子必须只依赖日历日 + 固定盐（此处 `mneme-sky:`），不要加 `Math.random()`。
3. 抽样从高提及池里取，避免星座全是边角实体。
4. 点击落点用与生成相同的逻辑坐标（1000×420 逻辑空间映射到画布）。
5. API 挂了要能重试，并让门厅其他块（丰碑）显示「…」而不是假的「—份」。

### 不要做

- 不要用外链「每日一句」冒充星座。
- 不要把未解锁的绝密实体画进当日星群。

## 8. 丝带续读与阅读现场

### 问题

传记是长程阅读。普通 SPA 刷新后回到门厅，读者会丢线。

### 做法

- 阅读位置 LRU（约 80 篇）存在本机。
- 丝带（`silk.ts` / `SilkRibbon`）记住卷、章、公开目录提示「按昨天停的地方往下翻」。
- 划线、本机现场不进库。
- 悬停预热：`prefetchSpace` / `prefetchDoc`；省流与 2G 跳过；私密路径永不预取。
- 入馆后空闲预热档案馆 → 书房 → 河。

### 复现

1. `localStorage` 键与结构写进注释，迁移时读旧写新。
2. 预取名单与导航名单同源，避免预热一个已下线的空间。
3. 预取失败忽略。预取不是功能路径。
4. 阅读器设置（字号、行宽、宋黑）与主题分键，互不覆盖。

## 9. 发版后仍能打开：哈希分包自愈

### 问题

Vite 文件名带内容哈希。用户或 Service Worker 握着旧 `index.html`，去拉已经不存在的 `River-xxxx.js`。若服务器把未知路径回成 `index.html`（SPA fallback），浏览器报「动态 import 失败」，整页像被掏空。

### 做法

1. **`/assets/*` 找不到 → 真 404**，永远不要 HTML（`server/server.mjs` 与 `deploy/server/server.mjs` 都要写）。
2. `lazySpace`：捕获 stale chunk 文案，**每个会话只 `location.reload()` 一次**。
3. Service Worker 对 HTML 网络优先，只缓存带哈希的 `/assets`。换缓存名（当前 `mneme-assets-v3`）才能甩掉旧壳。
4. 错误边界对过期分包说人话：请硬刷新，不把英文堆栈甩在门厅。

### 复现

1. 故意访问一个旧哈希 JS URL，确认 `Content-Type` 不是 `text/html`，状态是 404。
2. 用旧 `index-XXXX.js` 打开新站点，应自动刷新一次或提示硬刷新。
3. 发版清单里同时更新：HTML、assets、**数据库**、SW 缓存名（若策略变了）。

### 不要做

- 不要把 `/assets/foo.js` 交给前端路由。
- 不要无限 reload（`reloadOnce` 就是为了防止坏包死循环）。

## 10. 编辑排版（不是特效，但是门槛）

世界级阅读网站输在段落，不在光斑。本引擎的硬规则：

- 中文标题字距收紧（约 0.04–0.06em）；希腊文 kicker 保持宽字距。
- 正文 `line-height ≈ 2.05`，段首缩进 2em（紧凑块与纯图块除外）。
- `hanging-punctuation`、`orphans` / `widows`、`font-kerning`、`font-optical-sizing`。
- 插图按 plate 处理，灯箱可电影感模糊；`smooth` 档关掉重滤镜。
- 印刷：`@page` + 标题与段落避孤行。
- 跳过链接 `#mneme-main`；`lang="zh-CN"`（不要只写 `zh`）。

复现时先排一章真实中文长文，再调玻璃。

## 最小移植清单（给另一座库）

若你只想在自己的传记/档案库上复现「核心创新」，按这个顺序做，两周内能看见同类装置，而不必复制 ΜΝΗΜΗ 的文案与人物：

1. 只读 ingest + 私密目录零读取  
2. 单一 `privacy` 模块，私密 404、绝密 403  
3. 首屏壳探测  
4. 铬上玻璃、纸上正文、四档沉浸  
5. 弹窗关闭走采样粒子或干净淡出（减动效）  
6. 日期种子 + 真图谱的每日画面  
7. 资产 404 + 懒加载自愈  
8. 手势门闩控制媒体（致谢、自动播放、多标签互斥）
